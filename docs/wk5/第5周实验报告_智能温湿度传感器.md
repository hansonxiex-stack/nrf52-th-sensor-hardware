## 2. 本周完成情况

### 2.1 缝合过孔补齐：未连接数 56 → 0

第 4 周的 56 条未连接里，**GND 占 49 次、VDD 占 24 次**（每条未连接涉及两个网络，故次数之和大于 56）。根因不是布线，而是缝合过孔不够：32 个 GND 焊盘当时只有 4 个过孔，16 个 VDD 焊盘只有 2 个，够不到内层平面。

本周补齐后，全板过孔数 **66 个**，规格统一为 **外径 0.7mm / 钻孔 0.3mm**：

| 项目 | 数量 |
|---|---|
| 过孔总数 | 66 |
| 外径 / 钻孔 | 0.7 mm / 0.3 mm（全板一致） |
| 走线段 | 329 条 |
| 走线总长 | 723.5 mm |
| 网络数 | 47（走线上） |
| 铺铜区 | In1.Cu = GND 平面，In2.Cu = VDD 平面 |

**结果：`unconnected_items` 从 56 条降到 0 条。**

### 2.2 过孔与焊盘的位置关系

这一项单独拿出来说，因为判据容易搞错。**正确的判据是分两个圈看的：**

- **环压着焊盘 = 可以**。同网络下环与焊盘重叠只是"零长度连接"，没有副作用。
- **孔必须离焊盘边 ≥ 0.15mm**（0.10mm 是底线）。孔和焊盘贴太近，回流焊时**焊料会顺着孔壁虹吸跑掉**，造成焊点虚空。

注意：**孔净距 = 环净距 + 0.2mm** 是恒定的（0.7mm 外径 − 0.3mm 钻孔 = 0.4mm 环宽，两侧各 0.2mm）。所以调位置时要盯的是**孔**的净距，不是环的。

**处理结果**：

- 7 个过孔重新定位，做到「孔净距 0.15mm / 环压焊盘 0.05mm」。
- 1 处（C8 的 GND 过孔）**保持原位不动**。它被几何夹死：L1 焊盘下沿到 C8 焊盘上沿只有 0.770mm，而一个 0.7mm 过孔加上两侧各 0.2mm 需要 1.10mm；往右挪又有 SWDIO 走线斜穿。这里孔净距 0.070mm，是全板唯一低于 0.10mm 的，属于已知例外。

### 2.3 U1 散热焊盘的 9 个过孔（盘中孔）

nRF52810 的 EP（4.6×4.6mm）下面放了 3×3 共 9 个散热过孔，**全部落在焊盘内**——散热过孔必须在盘里才能把热导出去，这是设计意图不是失误。

**孔径决定：保持 0.3mm 不动。** 中途考虑过缩到 0.2mm 以减小吸锡量，但本工程 `min_through_hole_diameter = 0.3`，改小会直接报 9 条 `drill_out_of_range`。

> **这里记一条教训**：改过孔尺寸前必须**同时**查三条规则——`min_through_hole_diameter`（0.3）、`min_via_diameter`（0.6）、`min_via_annular_width`（0.2）。当时只查了后两条就动手，结果被第一条挡回来。

另外要纠正一个想当然的说法：**"孔小一点虹吸就弱"是错的。** 毛细压力与孔径成**反比**，孔越小吸得越**狠**；缩小孔径唯一的好处只是"能被吸走的锡总量变少"。**真正的根治手段是让板厂做树脂塞孔 + 电镀填平（IPC-4761 Type VII）**，这一项已列入下单前要跟嘉立创确认的事项。

### 2.4 丝印整理：53 条 → 1 条

第 4 周的 53 条丝印违规（`silk_overlap` ×10、`silk_over_copper` ×12 等）主因是 Y1 / C5 / C14 / C13 / R5 / L1 的 **Reference 字段位置压在焊盘或彼此身上**。

处理思路分三层，**从"改位置"到"改显示"逐级降级**：

1. **先挪**：Reference 字段尺寸调小、位置挪开，能解决大部分。
2. **挪不动的，关掉显示**：在 Footprint Properties 里 untick「Show」把该字段隐藏。
3. **实在没救的才删**：仅对确实无法通过位置/尺寸解决的。

这里有个关键区分：**Reference 字段在 F.SilkS / B.SilkS 上（会印出来），Value 字段在 F.Fab / B.Fab 上（本来就不印）**。所以只处理 Reference 就够了，Value 不产生丝印违规。

**结果：53 条降到 1 条**（见 2.5.2，属无需处理项）。

### 2.5 DRC 最终结果

```
** Found 4 DRC violations **
** Found 0 unconnected pads **
** Found 0 Footprint errors **
```

4 条全部是 `warning` 级，**没有一条 `error`**。电气类检查（`shorting_items`、`clearance`、`tracks_crossing`、`items_not_allowed`、`courtyards_overlap`、`pth_inside_courtyard`、`holes_co_located`、`unconnected_items`、`isolated_copper`、`drill_out_of_range`、`annular_width`、`via_dangling`）**全部为 0**。

下面逐条说明这 4 条。

#### 2.5.1 三条 `lib_footprint_mismatch` —— 都是主动修改，且都是预期内的

报告里的措辞是 **`Local override; warning`**，这句话本身就是答案：KiCad 在说"板上这份副本**故意**和库里不一样，**以板上为准**"。这是一条**告知**，不是缺陷。

**① U2（SHT4x，`Sensirion_DFN-4_1.5x1.5mm_P0.8mm_SHT4x_NoCentralPad`）**

板级实例内嵌了一个**四层 keepout zone**（F.Cu / B.Cu / In1.Cu / In2.Cu），系统库里没有这个 zone。这正是第 4 周按 SHT4x 手册 §5.3 做的**热隔离设计**（"There shall be no copper under the sensor other than at the pin pads"）。

因为改的是**板文件里的封装实例**、系统库 `Sensor_Humidity.pretty` 保持只读未动，所以 KiCad 认为"不一致"。

> ⚠️ **这是三条里最危险的一条**：从库更新会把 keepout 整体删掉，**而且不产生任何额外的 DRC 告警**——删完 DRC 照样全绿，但热隔离设计已经没了。

**② AE1（TI SWRA117D 2.4GHz 天线，`RF_Antenna:Texas_SWRA117D_2.4GHz_Left`）**

手工改过 **pad 2 的环形宽度（0.1 → 0.25mm）**。库里的 0.1mm 低于常见厂家的最小环宽要求，加宽后满足可制造性。

**③ U3（`Package_SO:SSOP-28_3.9x9.9mm_P0.635mm`）**

库里 28 个焊盘的局部角度是 **0°**，板上实例是 **270°**。原因是 U3 被**旋转 90° 放在 B.Cu**（封装 `at 131.5425 70 90`），焊盘角度参数随之调整。

**实际焊盘图形是正确的**，用三个独立证据交叉验证过：

- 焊盘尺寸 **1.2 × 0.4mm**，沿 0.635mm 节距方向的宽度是 **0.4mm** → 相邻焊盘留 **0.235mm 缝隙**（= 0.635 − 0.4），与第 4 周报告 §2.5 的记录一致；
- 14 个焊盘的 x 中心间距实测 **0.635mm**、两排间距 **5.2mm**，与库定义逐项相同；
- 28 个焊盘**每个都有走线精确落在焊盘中心**，DRC 无任何间距或短路违规。

反证：若焊盘在节距方向真是 1.2mm 宽，相邻焊盘会互相重叠 0.565mm，而它们分属 VDD / SDA / SCL / COM 等不同网络——DRC 一定会报死。现在不报，说明几何没问题。

**这三条的结论是同一条：**

> **U2 / AE1 / U3 三个器件，任何时候都不要点「Update Footprint from Library…」。** 其余 33 个封装可以正常更新。

三条 `lib_footprint_mismatch` 会在每次 DRC 都出现，**属于预期内的固定告警**，不要试图消除它。

#### 2.5.2 一条 `silk_over_copper` —— 元件自己的图形压自己的焊盘

```
@silk_over_copper: Silkscreen clipped by solder mask
    @(123.0, 86.4): Segment of LCD1 on B.Silkscreen
    @(122.0, 86.4): PTH pad 1 [COM0] of LCD1
```

LCD1 的**外框丝印**压到了**它自己的** 1 号通孔焊盘（COM0）。三个理由说明无需处理：

1. **是元件自己的图形压自己的焊盘**，不涉及任何外部器件，没有电气影响；
2. 阻焊开窗处本来就印不上丝印，**嘉立创的 CAM 会自动裁掉这一段**，是行业标准处理，不需要在文件里改；
3. 该线段位于 LCD 本体正下方，**装配后完全被玻璃盖住**，裁不裁都看不见。

如果要求报告全零，删掉这一小段即可，没有任何后果。



## 3. 本周遇到的问题及处理

**① 删了过孔但 DRC 没变**

U1 散热焊盘下原有一批**位置完全重合**的过孔（11 个叠在一起）。屏幕上只能看见一个，单击也只选中一个，删掉之后 DRC 依旧报错。

## 6. 本周总结

本周把 PCB 从"布局布线完成"推到了"可发板"：**未连接 56 → 0，丝印 53 → 1，DRC 只剩 4 条 warning、0 条 error。**

技术上本周最值得记的是**过孔与焊盘的判据要分两个圈看**——环压着焊盘没关系（同网、零长度连接），但**孔必须离焊盘边 ≥0.15mm**，否则回流焊时焊料会顺孔壁虹吸跑掉。而盘中孔（散热过孔）这件事上，正确答案不是缩孔径——**毛细压力与孔径成反比，孔越小吸得越狠**——而是让板厂做树脂塞孔电镀填平。

另外，本周把 DRC 的每一条残留告警都查到了根因，而不是"看着差不多就放过去"。三条 `lib_footprint_mismatch` 全部是主动修改（U2 的四层热隔离 keepout、AE1 的环宽、U3 的封装旋转），报告里的 **`Local override`** 就是 KiCad 在说"以板上为准"。其中 **U2 最需要警惕**：从库更新会静默删掉 keepout，且**不产生任何 DRC 告警**——DRC 全绿但热隔离已经没了。已把 **U2 / AE1 / U3** 三个器件列入"禁止从库更新封装"名单。
